# 数仓问答知识库设计

**目标：** 在 `project_extracted_docs/04_数仓问答知识库/` 建立一个长期维护的 Markdown 知识库，将用户后续提出的问题及完整解释按数仓实践路线归类，支持项目复盘、通用技术复习和面试准备。

## 1. 收录范围

知识库同时收录：

- 结合 AI 蓝军项目的数据仓库实战问题。
- Hive、Spark、Kafka、Flink、Hadoop、SQL 等通用技术问题。
- 数仓建模、指标体系、数据质量、元数据、数据安全、数据治理等方法论问题。
- 技术八股、项目追问和开放式场景题。

每个问题独立保存为一个 Markdown 文件。归档时使用统一复盘模板，不直接复制冗余聊天内容。

## 2. 目录架构

```text
project_extracted_docs/
└─ 04_数仓问答知识库/
   ├─ README.md
   ├─ 00_索引/
   │  ├─ 全部问题索引.md
   │  ├─ 按技术组件索引.md
   │  └─ 按面试场景索引.md
   ├─ 01_认识业务与规划架构/
   ├─ 02_数仓标准制定/
   ├─ 03_数据基建与分层建设/
   ├─ 04_数据应用/
   ├─ 05_数据质量/
   ├─ 06_元数据/
   ├─ 07_指标体系/
   ├─ 08_数据安全/
   ├─ 09_数据治理/
   ├─ 10_实时数仓/
   ├─ 11_数据服务/
   ├─ 12_技术基础与计算引擎/
   │  ├─ Hive/
   │  ├─ Spark/
   │  ├─ Kafka/
   │  ├─ Flink/
   │  ├─ Hadoop/
   │  └─ SQL/
   └─ 13_AI蓝军项目实战/
```

前 11 个主题与 `数仓建设实践路线.xmind` 的主体结构对应。`12_技术基础与计算引擎` 用于容纳不能自然归入建设阶段的组件原理题；`13_AI蓝军项目实战` 用于以项目本身为主要讨论对象的问题。

## 3. 分类规则

每个问题只能有一个正文文件和一个主分类，但可以通过索引和元数据拥有多个检索维度。

分类优先级：

1. 问题明确考查数仓建设阶段时，归入对应的 01 至 11 主题。
2. 问题主要考查组件原理、命令、配置或执行机制时，归入 12 下的具体组件。
3. 问题主要围绕 AI 蓝军项目背景、表设计、字段、SQL、指标或项目陈述时，归入 13。
4. 跨主题内容选择最主要的学习目标作为主分类，其余主题写入 `technologies` 和 `tags`，并在索引中建立入口。

示例：“如何保证这条链路的数据质量”归入 `05_数据质量`，同时标记 `AI蓝军项目`、`Hive`、`DQC`、`数据对账`、`场景题`。

## 4. 文件命名

单题文件采用：

```text
NNN_问题核心关键词.md
```

编号在所属目录内从 `001` 递增。标题使用自然语言，避免只写抽象缩写。例如：

```text
05_数据质量/001_如何保证离线数仓链路的数据质量.md
```

若问题需要更换主分类，可以移动文件并按新目录重新编号；所有索引链接必须同步更新。


模板规则：

- `原问题` 保留用户问题的原始语义。
- `核心结论` 用于快速复习。
- `完整解释` 保留完整推理、原理和实施步骤。
- `结合 AI 蓝军项目` 必须以当前仓库材料为依据；无直接关系时明确说明，不强行关联。
- `官方文档依据` 优先使用 Apache、产品官方文档或正式标准，并说明每个链接支撑的结论。
- `项目现状与生产方案` 必须区分已实现内容、资料无法证明的内容和建议补充的生产设计。
- `面试回答` 提供约一分钟的可口述版本。
- `高频追问` 提供可能的延伸问题和简要答案。

## 6. 索引设计

### README.md

知识库总入口，说明目录结构、推荐复盘路线、分类规则、文件模板和维护约定。

### 全部问题索引.md

按编号记录所有问题，至少包含标题、主分类、题型、难度、项目关联状态和相对链接。

### 按技术组件索引.md

按 Hive、Spark、Kafka、Flink、Hadoop、SQL、DQC 等组件或技术点建立交叉入口。正文不复制。

### 按面试场景索引.md

按基础八股、SQL 实战、项目追问、故障排查、方案设计、数据治理等场景建立入口。

## 7. 新问题归档流程

每次用户提出需要完整解答的问题时：

1. 结合当前项目材料确认项目事实。
2. 对可能变化、需要精确依据或用户要求搜索的内容检索官方文档。
3. 在对话中给出完整答案。
4. 判断主分类、题型、难度、技术组件和标签。
5. 检查是否存在语义高度重合的旧问题。
6. 不重复时创建新文件；高度重合时更新原文件并修改 `updated`。
7. 更新全部问题索引及相关交叉索引。
8. 检查 Markdown 结构、内部链接、官方链接和元数据。

## 8. 重复与冲突处理

- 标题不同但答案主体相同：合并为一个问题，在“高频追问”中保留另一种问法。
- 新问题只是旧问题的一个独立子主题：创建新文件，并在两篇文章中建立“相关问题”链接。
- 官方文档或项目实现发生变化：更新正文和 `updated`，在相关段落说明版本或当前仓库状态。
- 项目 SQL 与生产最佳实践冲突：同时保留项目现状和生产方案，不静默改写项目事实。

## 9. 首批内容

实施时创建完整目录和三个索引，并将当前已回答的“如何保证这条链路的数据质量”整理为：

```text
05_数据质量/001_如何保证离线数仓链路的数据质量.md
```

该文件应包含分层质量门禁、ODS 到 DWD 校验、DWD 到 DWM 的 JOIN 放大控制、DWM 到 ADS 指标对账、任务调度与重跑、当前项目 SQL 风险、官方 Hive/Spark 依据和面试回答。

## 10. 验收标准

- 目录结构与本设计一致。
- 每个问题只有一个正文文件。
- 首题包含模板规定的 11 个正文部分和完整元数据。
- 三个索引均能正确链接到首题。
- README 能说明如何查找、添加和复盘问题。
- 所有相对链接有效。
- 官方链接使用官方来源，并在正文中说明其用途。
- 不修改现有 PRD、数仓 SQL 和项目复盘内容。
- 不覆盖用户当前未提交的文件改动。
