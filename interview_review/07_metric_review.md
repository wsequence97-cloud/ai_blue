# AI 蓝军指标复盘

> 真实性边界：用户确认本人参与指标口径讨论、负责SQL开发和指标平台维护；现有仓库可支撑部分指标逻辑，但不能证明所有17类需求都由当前一张ADS完整覆盖。精确收益数字因统计周期、口径和来源遗忘，不在本文恢复。

## 1. 黑白样本结果真值

| 样本 | 审核结果 | 正确业务含义 | 指标归类 |
| --- | --- | --- | --- |
| 黑样本 | 隐藏/删除/封禁等拦截处置 | 风控有效识别 | 黑样本拦截 |
| 黑样本 | 通过或仍待审核 | 泄漏/未完成识别 | 黑样本泄漏 |
| 白样本 | 通过 | 正常放行 | 白样本正常放行 |
| 白样本 | 隐藏/删除/封禁等限制处置 | 误杀 | 白样本误杀 |

注意：`init`是待审核，不应永久混入“成功/失败”。若统计窗口截止时仍为`init`，应列为未完成；只有业务明确将窗口期内未识别视为泄漏时才进入泄漏分子。

## 2. 统一口径维度

每个指标必须同时确认：

1. 业务定义。
2. 分子和分母。
3. 去重主键。
4. 时间字段和统计窗口。
5. 前置还是后置审核。
6. 机审还是最终人审。
7. NULL、待审核、删除、重试、复投等边界。

默认建议：效果指标使用**后置审核**；任务级指标以`attack_task_id`去重，素材级以`resource_id`去重，工作流级以`workflow_runs_id`去重。

## 3. 17项核心指标

### 3.1 黑样本数

- 业务定义：统计窗口内进入蓝军投放/测评链路的黑样本任务数。
- 分子：`COUNT(DISTINCT attack_task_id)`，条件`ai_blue_sample_code=0`。
- 分母：无，数量指标。
- 去重主键：任务口径用`attack_task_id`；素材口径用`resource_id`，必须在指标名中写清。
- 时间口径：优先攻击任务创建/投放时间，不建议用素材创建时间替代。
- 阶段：后置链路。
- SQL思路：从输出DWM过滤黑样本后去重计数。
- 边界：同素材复投是否算多次取决于任务口径；删除/取消任务应排除。
- 当前表可算性：**可计算**，但当前ADS直接COUNT可能受一对多放大。

### 3.2 白样本数

- 定义：统计窗口内进入测评链路的白样本任务数。
- 分子：`COUNT(DISTINCT attack_task_id)`，条件`ai_blue_sample_code=1`。
- 分母：无。
- 去重、时间、阶段：同黑样本数。
- 边界：样本属性为空或异常值单列，不塞入黑/白。
- 当前表可算性：**可计算**，需任务级去重。

### 3.3 黑样本拦截数

- 定义：黑样本被机审或最终审核执行隐藏、删除、封禁等限制处置的任务数。
- 分子：黑样本且结果非`pass/init`的去重任务数。
- 分母：黑样本数（计算拦截率时）。
- 去重主键：`attack_task_id`；同任务多审核取最终有效审核。
- 时间：攻击时间或审核完成时间二选一，并固定。
- 阶段：后置；机审拦截与最终拦截分开。
- SQL：先按`biz_id`取最终审核，再与任务关联。
- 边界：NULL/`init`列为未完成；不能自动算拦截。
- 当前表可算性：**可计算**。

### 3.4 黑样本泄漏数

- 定义：黑样本被通过，或在定义的审核完成窗口后仍未被有效识别的任务数。
- 分子：黑样本且最终结果`pass`；若业务确认，超时`init`也纳入。
- 分母：黑样本数（计算泄漏率时）。
- 去重主键：`attack_task_id`。
- 时间：审核完成截止窗口必须明确。
- 阶段：后置。
- SQL：最终审核状态CASE分类。
- 边界：不能把所有`init`无条件当泄漏；未关联审核可能是链路延迟。
- 当前表可算性：**部分可算**，缺明确超时窗口。

### 3.5 黑样本拦截率

- 定义：黑样本中被正确拦截的比例。
- 分子：黑样本拦截数。
- 分母：已完成审核的黑样本数，或全部黑样本数；必须由业务确定。
- 去重主键：`attack_task_id`。
- 时间/阶段：与分子分母保持一致，后置。
- SQL：`black_block_cnt / NULLIF(black_total_or_completed_cnt,0)`。
- 边界：分母为0返回NULL，不返回0；机审和最终审核分别计算。
- 当前表可算性：**可派生**。

### 3.6 黑样本泄漏率

- 定义：黑样本未被正确识别的比例。
- 分子：黑样本泄漏数。
- 分母：与拦截率采用同一黑样本集合。
- 去重/时间/阶段：同上。
- 边界：只有分类完全互斥且覆盖时，拦截率+泄漏率=100%；存在未完成则还需加未完成率。
- 当前表可算性：**部分可派生**，待审核边界需确认。

### 3.7 白样本正常放行数

- 定义：白样本被最终审核正常通过的任务数。
- 分子：白样本且最终结果=`pass`的去重任务数。
- 分母：白样本数（计算通过率时）。
- 去重主键：`attack_task_id`。
- 时间/阶段：后置，按攻击或审核完成时间。
- 边界：`init`不是正常放行；`show/recover`需确认是最终恢复后的通过还是历史动作。
- 当前表可算性：**可计算**。

### 3.8 白样本误杀数

- 定义：白样本被隐藏、删除、封禁或其他限制处置的任务数。
- 分子：白样本且最终结果非`pass/init`的去重任务数。
- 分母：白样本数（计算误杀率时）。
- 去重主键：`attack_task_id`。
- 时间/阶段：后置。
- 边界：后续人工纠正需决定按首次处置还是最终处置；两者可分别做机审误杀与最终误杀。
- 当前表可算性：**可计算**。

### 3.9 白样本通过率

- 定义：白样本被正确放行的比例。
- 分子：白样本正常放行数。
- 分母：已完成审核或全部白样本数，需统一。
- 去重主键：`attack_task_id`。
- 时间/阶段：后置。
- 边界：存在未完成时，通过率与误杀率不一定相加100%。
- 当前表可算性：**可派生**。

### 3.10 白样本误杀率

- 定义：白样本被错误限制的比例。
- 分子：白样本误杀数。
- 分母：同一统计集合的白样本数。
- 去重/时间/阶段：同白样本通过率。
- SQL：`white_false_positive_cnt / white_total_or_completed_cnt`。
- 当前表可算性：**可派生**。

### 3.11 机审转人工率

- 定义：进入机审的样本中，被转交人工审核的比例。
- 分子：`is_manual=1`的去重审核业务对象/任务数。
- 分母：进入机审的全部有效样本数。
- 去重主键：审核对象口径用`biz_id`，任务口径用`attack_task_id`。
- 时间：机审时间或攻击时间，不能混用。
- 阶段：建议后置；如统计生成前审核，必须单独命名。
- SQL：先取每个业务对象最终机审转人工标志。
- 边界：重复机审、人工回流、缺少机审记录需要规则。
- 当前表可算性：**可计算**，当前ADS未直接输出该率。

### 3.12 人审纠正率

- 定义：机审结论与最终人审结论不一致，并由人审纠正的比例。
- 分子：有人工审核且机审/人审分类结果相反的去重任务数。
- 分母：实际进入人工审核且两种结论均完整的任务数。
- 去重主键：`attack_task_id`或`biz_id`。
- 时间：最终人审完成时间。
- 阶段：后置。
- SQL：将机审和人审都归一为“拦截/通过”，再比较。
- 边界：不能直接比较原始code字符串；`init`、NULL排除或单列。
- 当前表可算性：**可计算**，需明确最终审核记录。

### 3.13 工作流成功率

- 定义：Dify工作流运行成功次数占有效运行次数的比例。
- 分子：成功状态的`COUNT(DISTINCT workflow_runs_id)`。
- 分母：排除取消/测试（若有明确规则）后的有效运行数。
- 去重主键：`workflow_runs_id`。
- 时间：工作流创建或完成时间。
- 阶段：生成过程，不是审核前后效果指标。
- SQL：从workflow DWD按应用/工作流/日期聚合。
- 边界：重试按运行次数还是业务请求最终成功需提供两套口径；后者按`request_id`聚合。
- 当前表可算性：**可计算**。

### 3.14 平均耗时

- 定义：工作流有效运行的平均完成耗时。
- 分子：有效运行`elapsed_dur`之和。
- 分母：具有合法耗时的运行数。
- 去重主键：`workflow_runs_id`。
- 时间：完成时间归属日期或创建日期，固定一种。
- 阶段：生成过程。
- SQL：`AVG(elapsed_dur)`，同时建议P50/P95/P99。
- 边界：失败、超时、NULL和异常负值需分别统计；平均值易受长尾影响。
- 当前表可算性：**可计算**。

### 3.15 Token消耗

- 定义：工作流在统计窗口消耗的Token总量或单次平均Token。
- 分子：`SUM(total_tokens)`；单次平均再除以有效运行数。
- 分母：总量无分母；平均值以运行数为分母。
- 去重主键：`workflow_runs_id`。
- 时间：工作流完成/创建时间。
- 阶段：生成过程。
- SQL：按`app_id/workflow_id/date`聚合。
- 边界：重试会真实产生Token成本，成本口径应计入；业务请求效率口径可另按request汇总。
- 当前表可算性：**可计算**。

### 3.16 攻击任务数

- 定义：统计窗口内有效攻击任务数量。
- 分子：`COUNT(DISTINCT attack_task_id)`。
- 分母：无。
- 去重主键：`attack_task_id`。
- 时间：攻击任务创建/实际投放时间；当前只有创建时间材料时需说明限制。
- 阶段：后置投放链路。
- 边界：取消、删除、重复重试、同任务多素材需按任务表业务定义处理。
- 当前表可算性：**可计算**。

### 3.17 有效素材数

- 定义：满足质量要求且可用于攻击的唯一素材数量。
- 分子：符合“有效”规则的`COUNT(DISTINCT resource_id)`。
- 分母：无；计算可用率时以生成素材总数为分母。
- 去重主键：`resource_id`。
- 时间：素材创建、审核通过或首次可用时间需统一。
- 阶段：生成后、投放前。
- SQL：资源DWD关联内容/审核/使用状态后筛选。
- 边界：`is_used=1`只能证明使用过，不自动等于有效；有效规则可能还需生成成功、内容完整、未删除、审核通过。
- 当前表可算性：**部分可算**，当前表缺完整“有效素材”业务标志。

## 4. 推荐统一SQL分类层

先在任务粒度生成互斥分类，再聚合，避免每个指标重复写条件：

```sql
CASE
  WHEN ai_blue_sample_code=0 AND final_result='blocked' THEN 'black_blocked'
  WHEN ai_blue_sample_code=0 AND final_result='pass' THEN 'black_leaked'
  WHEN ai_blue_sample_code=1 AND final_result='pass' THEN 'white_passed'
  WHEN ai_blue_sample_code=1 AND final_result='blocked' THEN 'white_false_positive'
  ELSE 'unfinished_or_unknown'
END AS evaluation_result
```

前置条件：先按`biz_id`选取正确的最终审核记录，再映射统一状态；不能在含多条审核记录的宽表上直接分类。

## 5. 指标DQC

- `黑拦截 + 黑泄漏 + 黑未完成 = 黑样本总数`。
- `白放行 + 白误杀 + 白未完成 = 白样本总数`。
- 各率在`[0,1]`范围内；分母为0返回NULL。
- 机审转人工数不得大于机审总数。
- 人审纠正数不得大于进入人工且结论完整的样本数。
- 工作流成功数不得大于有效运行数。
- Token和耗时不得为负；异常值单独统计。
- 前后置审核`biz_id`交集为0。

## 6. 现有资料覆盖结论

| 覆盖状态 | 指标 |
| --- | --- |
| 当前字段可直接计算或派生 | 黑/白样本数、黑拦截、白放行、白误杀、机审转人工、工作流成功率、耗时、Token、攻击任务数 |
| 需要最终审核/超时窗口规则 | 黑泄漏、黑拦截率/泄漏率、白通过率/误杀率、人审纠正率 |
| 需要补充业务有效性规则 | 有效素材数 |

当前ADS截图中虽有25个物理字段，但存在时间口径、一对多放大、字段命名和NULL分类问题。面试中应说“17类业务指标可拆成多个物理字段”，不能说“ADS恰好只有17列”。

## 7. 收益数字边界

3人/天、白样本+50%、黑样本+20%、黑样本成功率+10%、白样本攻击成功率+5%、机审38%被用户确认为团队验收结果，但统计周期、分子分母和来源遗忘。因此：

- 不用这些数字证明个人SQL效果。
- 找回验收报告、指标平台快照或导师确认前，不在严格面试中主动报精确值。
- 可以说“项目团队验收确认运营效率和样本效果得到改善，但我目前无法可靠复述精确统计口径”。
