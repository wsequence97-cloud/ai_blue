# 问题名称

## 一、面试主答

优先控制在45～60秒、约200～350字，并根据题型按3～4点自然作答。关键因果、具体例子或必要边界无法省略时可适当延长，不为凑字数删掉理解核心。

1. 先直接回答本质或定义；
2. 再说明核心机制或执行过程；
3. 接着说明使用场景、解决方案或选型；
4. 最后补充边界、缺点或注意事项。

## 二、关键流程或代码

只保留理解本题必需的一段流程、数据变化示例、对比表、物理计划，或优先不超过20行的SQL。不要重复面试主答；必要细节可保留，但要删去重复和弱相关扩展。

## 三、本次讨论后的复盘结论

- **我原来容易混淆的点：** 只记录本次讨论中用户真实表达过的困惑；没有时明确写“本次未形成已确认的混淆点”。
- **修正后的理解：** 写讨论后确认的认识。
- **以后判断问题的标准：** 写可复用的判断依据。
- **一句话记忆：** 写便于复习的短句。

## 五、项目或开发场景映射

- **通用开发场景：** 用一个简短例子解释。
- **本项目可真实使用的表述：** 只写仓库材料和用户讨论能够支持的事实。
- **不能过度表述的部分：** 标明学习假设、未上线方案、未验证收益或并非本人负责的内容。
