# Hive内部表和外部表的区别

## 一句话结论

内部表（托管表）与外部表的本质区别是Hive是否管理数据生命周期，而不是数据是否放在HDFS。删除托管表通常会删除元数据和数据文件；删除外部表通常只删除元数据，底层文件保留。

## 核心因果链

已有目录的数据需要被Hive查询但不能因删表丢失 → 建外部表，仅登记结构和位置
Hive产出的结果希望由Hive统一治理 → 建托管表，Hive管理文件、元数据和统计信息
DROP托管表 → 通常删除元数据及数据文件
DROP外部表 → 通常仅删除元数据 → 可重新建表映射原目录
二者都可位于HDFS或其他兼容存储 → 物理存储系统不等于生命周期归属

## 实际开发例子

现有项目的ODS和DWD建表SQL都使用`CREATE TABLE`且未写`EXTERNAL`，按Hive默认语义均为托管表。若原始文件需独立保留，应按实际目录治理规则改用外部表，避免删表影响源文件；建表前还要明确目录由谁承担创建、清理、复用、迁移和归档责任。

## 易错点

- 外部表不是只读表，也可以INSERT或INSERT OVERWRITE。
- 两类表都可存HDFS，不能用存储介质区分。
- 外部表设`external.table.purge=true`时，删表也会删数据。

## 30秒面试回答

Hive内部表和外部表的核心区别是Hive是否负责数据生命周期。内部表默认由Hive管理，删除表时通常会连同数据文件一起删除，适合Hive加工生成、可由数仓统一治理的结果数据。外部表主要是为已有目录建立元数据映射，删除表时通常只删除表定义，文件仍保留，适合不希望Hive删掉的原始或共享数据。两者都能存放在HDFS，也都可以写入；外部表不是只读表。实际建表前要先确认数据目录的所有权和删除责任。

## 高频追问

- ODS为什么常用外部表：保护采集源文件，便于多个系统共享。
- 外部表能否写入：可以，INSERT、INSERT OVERWRITE等均可使用。
- 外部表删除数据的例外：`external.table.purge=true`。
