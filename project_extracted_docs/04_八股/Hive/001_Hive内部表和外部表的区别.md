# Hive内部表和外部表的区别

## 一、面试主答

1. Hive内部表也叫托管表，外部表的本质区别是Hive是否负责数据生命周期，而不是数据是否存放在HDFS。两类表都可以映射HDFS等兼容存储中的数据。
2. 托管表默认由Hive管理元数据和数据文件，`DROP TABLE`时通常同时删除表定义和底层数据，适合由数仓加工生成并统一治理的结果数据。
3. 外部表使用`EXTERNAL`声明，主要为已有或共享目录建立元数据映射。删除表时通常只删除元数据，文件仍保留；外部表并不是只读表，也可以执行写入操作。
4. 选型不能只背“ODS外部、DWD内部”，而要先确认目录所有权和删除责任。若设置清理类属性，外部表删表也可能删除数据，所以删除前应核对建表属性和平台规则。

## 二、关键流程或代码

| 对比项 | 内部表（托管表） | 外部表 |
| --- | --- | --- |
| 创建方式 | 默认`CREATE TABLE` | `CREATE EXTERNAL TABLE` |
| 数据责任 | Hive负责生命周期 | 通常由外部系统或共享目录负责 |
| 删除表 | 通常删除元数据和数据 | 通常只删除元数据 |
| 适用场景 | Hive加工并统一治理的结果 | 已有、共享或需独立保留的数据 |

## 三、本次讨论后的复盘结论

- **我原来容易混淆的点：** 本次讨论没有形成经用户确认的混淆点。
- **修正后的理解：** 判断内外部表应看数据生命周期归谁管理，不能按“本地还是HDFS”或“能不能写入”区分。
- **以后判断问题的标准：** 建表前先问数据目录由谁创建、删除、复用、迁移和归档，再决定是否交给Hive托管。
- **一句话记忆：** 内外部表看删除责任，不看存储介质。

## 四、高频追问

### 追问1：外部表可以写入吗？

可以，`EXTERNAL`描述的是生命周期管理关系，不代表只读。是否允许`INSERT`或`INSERT OVERWRITE`还要结合文件格式、权限和具体平台能力判断。

### 追问2：删除外部表一定不会删除数据吗？

不能说绝对不会。Hive通常只删除外部表元数据，但清理属性或平台扩展可能改变行为，例如启用`external.table.purge`时可能同时清理数据；删除前必须检查表属性。

### 追问3：ODS层一定要建外部表吗？

不一定。若ODS映射采集系统保留的共享原始目录，外部表更安全；若文件完全由Hive链路生成并由数仓统一负责生命周期，也可以选择托管表，关键仍是数据所有权。

## 五、项目或开发场景映射

- **通用开发场景：** 第三方每天投递到固定HDFS目录的日志可建外部表；Hive加工出的临时或结果数据可按治理要求建托管表。
- **本项目可真实使用的表述：** 仓库中的蓝军ODS、DWD建表SQL使用`CREATE TABLE`且未写`EXTERNAL`，并按`pt`分区，这是现有材料能够确认的语法事实。
- **不能过度表述的部分：** 未看到真实存储目录、平台删除策略和表属性验证结果，不能声称生产删表一定会删除或保留文件，也不能擅自认定现有ODS设计错误。
