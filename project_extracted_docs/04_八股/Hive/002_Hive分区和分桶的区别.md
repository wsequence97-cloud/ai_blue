# Hive分区和分桶的区别

## 一句话结论

分区按字段实际取值将数据拆为多个目录，主要依靠分区裁剪减少扫描；分桶按字段哈希将每个分区内的数据稳定写入固定数量的桶。分桶不改变Join或聚合的正确性，而是为长期复用同一Key的查询创造减少重复Shuffle的机会。

## 核心因果链

查询经常按`pt`过滤 → 数据按`pt`建目录 → 只扫描命中分区
单个分区仍大且长期按同一Key关联 → 按Key哈希写入固定桶文件
普通Join未预组织数据 → 运行时按Join Key Shuffle → 同Key临时汇集
两表按相同Join Key、兼容桶规则正确落桶 → 可按对应桶处理 → 可能减少Shuffle
桶字段与本次Join Key不同 → 仍需按Join Key重新Shuffle

## 实际开发例子

现有ODS和DWD表均按`pt`分区，DWD SQL用`WHERE t0.pt='${bizdate}'`只处理当天分区数据。若未来两张大表长期按`resource_id`关联，才评估按该字段分桶；当前按低基数编码关联维表，不应仅因Join就分桶。

## 易错点

- 分桶不是默认操作，需`CLUSTERED BY`显式声明。
- 桶数不等于Reduce数；后者是一次Job的运行并行度。
- 哈希分桶也可能倾斜，热点Key会持续落入同一桶。

## 30秒面试回答

Hive分区和分桶解决的问题不同。分区按字段取值把数据存为多个目录，常用日期字段；查询带分区条件时可以裁剪目录，避免扫描历史全量数据。分桶是在每个分区内部按字段哈希写入固定数量的桶，使相同Key稳定落在同一个桶。普通Join即使不分桶，也会在运行时通过Shuffle让同Key汇集，因此结果不会受影响；但若两张大表长期按同一Key、按兼容规则正确分桶，执行时可能按对应桶处理，减少重复Shuffle。桶数不是Reduce数，分桶也不保证数据绝对均匀。

## 高频追问

- 分区字段怎么选：常过滤、基数适中，如日期或小时。
- 分桶何时有价值：大表长期按同一高基数Key关联或抽样。
- 分桶与Shuffle：前者长期存储布局，后者本次任务临时重分区。
