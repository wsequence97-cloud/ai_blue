# 数据开发八股复习库

本目录只沉淀能够在数据开发面试中直接复习和口述的短篇卡片，不保存长篇教程、完整聊天记录、项目审计报告或大量扩展资料。

## 学习与写入方式

1. 先在对话中理解和追问知识点，不立即生成文件。
2. 仅在明确提出“沉淀本题”“整理成复习卡”或“结束这个问题”后写入。
3. 后续追问仍属于同一知识点，应更新原卡，不因换一种问法重复建卡。
4. 卡片使用`NNN_问题核心关键词.md`命名，一个问题只归入一个主模块；跨模块只在索引中建立关联。
5. 新增或更新卡片后同步维护模块索引；复盘进度只在用户明确要求或盘问结束并确认等级后更新。

## 卡片生成规范

每张卡片统一包含六部分：面试主答、关键流程或代码、本次讨论后的复盘结论、高频追问、项目或开发场景映射、参考依据。

- **面试主答：** 优先控制在45～60秒、约200～350字，按3～4点口语化回答。第一两句直接回答问题，同时覆盖“是什么、为什么、怎么用”和必要边界；关键因果或必要例子无法省略时可适当延长。
- **关键流程或代码：** 只放一段必要内容，可用流程、数据变化示例、对比表、物理计划或优先不超过20行的SQL，不重复主答。
- **讨论复盘：** 只记录本次对话中用户真实出现并已确认的认知变化。没有讨论依据时明确写暂无，不编造用户误区。
- **高频追问：** 保留3个最有价值的问题，优先用2～4句话给出可直接口述的短答案；必要时保留解释清楚边界所需的信息，不只列关键词。
- **场景映射：** 必须区分通用示例、仓库资料支持的项目事实，以及学习假设或不能过度表述的内容。
- **参考依据：** 保留1～2条官方文档、官方源码说明或正式设计文档，只说明其支撑的结论，不复制原文。

普通题以600～1000字为复习友好的目标，复杂场景可适当延长；篇幅不是硬性删减条件。优先删除重复定义、冷门扩展、参数清单和与面试主问题无关的内容，但不得为满足字数而删除关键因果、具体例子、选型依据或必要边界。

## 按题型组织主答

- 概念题：定义 → 核心特征 → 作用 → 边界。
- 对比题：本质区别 → 存储或执行差异 → 使用场景 → 选型。
- 流程题：触发条件 → 核心步骤 → 组件职责 → 异常或注意点。
- 优化题：问题表现 → 原因定位 → 治理方案 → 验证方式。
- 项目场景题：背景 → 难点 → 我的处理 → 结果 → 复盘。

题型只决定回答逻辑，不要求机械复用相同措辞。

## 事实与表达边界

1. Hadoop、Hive、Spark等技术事实优先依据Apache官方文档、官方源码说明或正式设计文档。
2. 用容易理解的中文解释，不大段翻译官网，不为显得完整堆叠术语和参数。
3. 涉及AI蓝军项目时，以仓库中的PRD、SQL和复盘材料为准；不得虚构数据规模、性能收益、线上故障或个人职责。
4. 项目未实际采用的技术只能标为通用示例或学习假设，不能包装成生产经历。

## 模块与掌握程度

- `Hadoop/`：HDFS、YARN及Hadoop通用知识。
- `MapReduce/`：MapReduce执行模型与机制。
- `Hive/`：Hive表设计、SQL执行与优化。
- `Spark/`：Spark执行原理、调优与开发实践。
- `数仓建模/`：维度建模、事实表粒度和数仓分层设计。

掌握程度分为L1（看过）、L2（能复述定义）、L3（能解释因果）、L4（能结合场景回答追问）。
