# 事实表类型

## 一、面试主答

1. 按Kimball的基本粒度，事实表有事务、周期快照、累积快照三类；面试中还常补充无事实事实表。选型先定义“一行事实代表什么”。
2. 事务事实表一行记录一次业务事件，例如订单明细、支付或点击。粒度是发生瞬间，通常追加写入，适合明细追溯和灵活汇总。
3. 周期快照事实表按天、周、月记录实体状态或汇总，例如每日库存、每日内容量。粒度是“实体＋周期”，即使无业务也常保留零或空记录，支持连续趋势分析。
4. 累积快照事实表一行代表完整流程，例如订单履约；流程推进时更新支付、发货、完成等里程碑，适合计算阶段耗时。无事实事实表只记录关系或事件，不存数值度量。

## 二、关键流程或代码

```text
订单O1001：6-01创建 → 支付 → 发货；6-03签收

事务表：4行，分别记录创建、支付、发货、签收事件。
周期快照：6-01一行“已发货”；6-02再一行“已发货”；6-03一行“已签收”。
累积快照：始终一行O1001，逐步补齐创建、支付、发货、签收时间。
无事实表：用户U01在6-01曝光资源R100一行，不保存金额、数量等指标。
```

## 三、本次讨论后的复盘结论

- **我原来容易混淆的点：** 本次未明确个人误区；需统一“三种基本类型”和“无事实表扩展”的计数口径。
- **修正后的理解：** 三种基本类型按粒度区分：事件、固定周期状态、完整流程；无事实表没有数值度量。
- **以后判断问题的标准：** 先写清一行代表事件、某天状态还是一个流程，再决定追加、周期新增或更新同一行。
- **一句话记忆：** 一次事件用事务，一段时间用快照，一条流程用累积。

## 四、高频追问

### 追问1：周期快照和累积快照怎么区分？

周期快照按固定频率产生新行，例如每天每个商品一行库存。累积快照是一条流程一行，随流程推进更新里程碑；前者看每天状态，后者看过程耗时。

### 追问2：无事实事实表没有指标，有什么价值？

它可通过行数或维度组合回答“某事是否发生、发生多少次”。例如记录用户、内容、日期、渠道的曝光关系后，可统计曝光次数或覆盖用户数。

### 追问3：累积快照适合记录完整历史吗？

不完全适合。它通常保留当前或最终里程碑，状态反复变化时细节会被覆盖。需要完整轨迹时，应同时保留事务事件表或增加历史追踪。

## 五、项目或开发场景映射

- **通用开发场景：** 订单明细建事务表；商品每日库存建周期快照；订单履约节点建累积快照；用户曝光内容建无事实事实表。
- **本项目可真实使用的表述：** `ads_operation_com_ovewview_target`按`pt`分区，并按内容类型、日期汇总多个`COUNT`指标，具有按周期汇总分析的特征。
- **不能过度表述的部分：** 仅凭现有SQL不能断言该ADS表的完整业务粒度，也没有材料证明项目已建设按同一流程行持续更新的累积快照事实表。
